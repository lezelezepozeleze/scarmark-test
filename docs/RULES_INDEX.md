# Rules index

Where each game mechanic lives in the CURRENT code (1.0.57-beta). Keep it accurate in the same change as any move or new mechanic (docs/AGENTS.md).

Columns:
- Config location: where the rule VALUES live: a file in module/config/ (authoritative), or "hardcoded" = the number is still a literal in code, not in config (the full list is the last section). CONFIG.SCARMARK (module/config.mjs) only assembles module/config/ and module/rules/ for macros, sheets and templates.
- Rule function: the authoritative calculation. Pure ones live in module/rules/ (all re-exported by rules/index.mjs); a function in module/data/, module/helpers/ or module/sheets/ is a thin reader of the actor or a workflow around the pure function.
- Consumers: code that calls the function or uses its result. Templates (templates/) only display values, so a row lists them only where a template reads a config key.
- Golden fixture: file in tests/golden/ and its mechanic name (the adapter key in tests/golden/adapters.mjs); sub-cases name the consumer where a fixture covers several. "none" = no golden coverage. The *-sample.json real-data fixtures are committed coverage-selected samples of the local-only full sets in tests/golden/local/ (gitignored, see tests/golden/README.md); the same rows hold for the full sets.
- DUPLICATED = the same rule is written more than once; the differences between the copies are listed in the row.

All paths are relative to module/. Line numbers are left out on purpose (they go stale); search for the function name.
